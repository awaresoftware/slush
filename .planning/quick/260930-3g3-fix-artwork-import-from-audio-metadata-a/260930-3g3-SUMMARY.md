# Quick 260930-3g3: Fix artwork import + web artwork search — Summary

Album artwork now imports from the best picture in a file rather than index 0, is written through one canonical
WebP/600px/q80 path with a provenance column that makes a user's own choice permanent, auto-fetches the 485 artless
albums, and can be searched, replaced, uploaded or removed from the album page.

## What was built

**Provenance and one canonical write path (D3, D4).** `ArtworkSource` (`embedded`/`fetched`/`uploaded`/`manual`) with
`isAuto()` marking the two machine-detected tiers. `Album::storeCoverArt(string $imageData, ArtworkSource $source)`
is the single writer for all four paths: it refuses to overwrite a `Manual`/`Uploaded` cover, rejects undecodable
bytes via `getimagesizefromstring()` plus a shared 100px minimum edge, scales down to 600px, encodes WebP q80 at
`covers/{id}.webp`, and deletes a differently-extended predecessor. `Album::clearCoverArt()` is the single Remove
primitive. The `$mime` parameter is gone, so the MIME→extension mismatch class has no reason to exist.

**Corrected extraction (D7).** `extractCoverArt()` collects candidates from both `id3v2.APIC` and `comments.picture`,
filters them through `Album::coverIsUsable()`, then ranks front-cover-first and by pixel area. Re-extraction replaces
a cover only when it is missing or degenerate — a real image on disk is still left alone, so a second track cannot
clobber it. A still-artless album now queues `FetchAlbumArtwork` (D6), deduplicated per album.

**A fetch job that does not block a worker (D6).** `usleep(1100000)` replaced by a one-second `Cache::add` token that
releases the job back onto the queue; `ShouldBeUnique`, `backoff() => [60, 300]`, `$tries = 5`. A `Manual`/`Uploaded`
cover short-circuits the job; an auto-sourced cover is *upgraded* rather than skipped. A non-image body records a
miss instead of burning retries.

**Graceful degradation (D10).** All six `<img>` cover sites render the musical-note glyph first and overlay the image
with `absolute inset-0` + `onerror="this.remove()"`, so a 404 reveals the placeholder. The Media Session artwork MIME
is derived from the file extension.

**The picker (D1, D2, D8, D9).** `ArtworkSearch` (iTunes + Deezer, one normalised shape, per-provider failure
isolation, 24h cache) and `ArtworkModal` (search / apply / upload / remove / reset-to-auto), mounted on the album page
with a "Change artwork" button. Search is throttled to 20 per user per minute with an explicit message.

**The backfill command (D5).** `albums:backfill-artwork` re-encodes referenced covers to 600px WebP, prunes orphans,
clears degenerate covers, refuses to run unless the public disk root really is the public disk, and ships `--dry-run`.
**Not run** — that is the operator's call at the checkpoint.

## Deviations from plan

### Task sequencing

**Task 1's verify command includes the two job test files, but the plan assigns their fixture updates to Task 2.**
The new `storeCoverArt` validation gate rejects those files' fake-byte fixtures (`'image-bytes'`, a 1×1 JPEG, a
literal `'original-data'`), so Task 1 could not verify green without them. The fixture changes the plan pre-declares
for Task 2 were folded forward into Task 1's commit; Task 2 then owned the behaviour rewrites. Nothing was weakened —
the three cover tests kept their assertions and gained a realistic fixture.

### 1. [Rule 1 - Bug] Backfill safety guard defeated `Storage::fake()`

The plan's guard ("assert the public disk root resolves inside `storage/app/public`") makes the command silently bail
under `Storage::fake()`, which the plan's own test spec requires. The guard now allow-lists exactly two roots —
`storage/app/public` and `storage/framework/testing/disks/public` — and returns a failure exit code rather than
silently succeeding. The production check is unchanged; a misconfigured disk is still refused.

### 2. [Rule 1 - Bug] `getOriginal()` read after the update

`$album->getOriginal('cover_art_path')` was called after `$album->update(...)`, so the "old path" could resolve to the
new one and the predecessor would never be deleted. The path is now captured before the write.

### 3. [Rule 2 - Missing critical functionality] A failed search must not be cached for 24h

`Cache::remember` around a provider call would cache the `[]` returned by a 500 or a timeout, blanking a tab for a
day after one blip. Failures are now returned without being cached; only definitive answers (including empty ones)
are stored. Covered by `a failed search is not cached, so the next attempt retries`.

### 4. [Rule 2 - Missing critical functionality] Two throttling correctness bugs

- `RateLimiter::attempt` returns the callback's value. Returning `$this->results` meant an **empty result set read
  as a throttle**, telling the user "too many searches" on a perfectly normal empty search. The closure now returns
  `true`.
- `$this->provider` is client-supplied. `->{$this->provider}()` on an unvalidated value is a call to an undefined
  method. It is now constrained to the two known providers.

### 5. [Rule 2 - Missing critical functionality] Result entries need an id, not just an image

A candidate with a blank `id` would collide with every other blank-id entry and resolve to the wrong image in
`applyRemote`. Entries without an id are now skipped alongside entries without an image.

### 6. [Rule 2 - Missing critical functionality] The dedupe token must be cleared on Remove

`ExtractAudioMetadata` now dedupes its fetch dispatch with a one-hour `album-artwork-attempt:{id}` token (needed
because `ShouldBeUnique` cannot collapse the burst under `Queue::fake`, and because a 200-track scan would otherwise
enqueue 200 lookups). `Album::clearCoverArt()` forgets that token, so Remove and the backfill's degenerate-clear
re-arm detection immediately.

### Deliberate substitutions

- **`x-ui.segmented-control` instead of `x-mary-tabs`.** The project already has a segmented-control component and
  `x-mary-tabs` is used nowhere; its own comment documents that an Alpine-only tab state leaves Livewire unpatched.
  Reuse beats introducing an untested third path.
- **`x-mary-icon` / existing tokens only** in the modal, per the tailwindcss-development skill and the sibling
  `upload-modal.blade.php` structure.
- **The rate limiter test lives in `ArtworkModalTest`**, not `ArtworkSearchTest` — it exercises the Livewire `search()`
  action, which is where the limiter lives.

## Known limitations (deliberate, documented ceilings)

- **`album-artwork-mb-gate` serialises the whole library.** 485 albums take ~485s of wall clock regardless; the win is
  that no worker is asleep for it. A job that cannot take the slot within `$tries = 5` releases-and-exhausts. The
  failure is benign — nothing is recorded as a permanent miss — and the next scan or `albums:fetch-missing-artwork`
  retries. Marked with a `ponytail:` comment naming the upgrade path (a per-host rate limiter with jittered backoff).
- **`/storage/covers/*` is still unauthenticated** and paths are guessable from album ids. Recorded as T-06
  (low, accept); fixing it means a signed-URL or private-disk migration, a different phase.

## Threat flags

No surface beyond the plan's `<threat_model>`. All eight register entries were implemented as specified: `applyRemote`
accepts only `provider` + id and resolves the URL server-side (T-01); `storeCoverArt`'s decode + dimension gate is the
byte-validation backstop behind the `image|max:2048` rule (T-02); the backfill command allow-lists its disk root and
ships `--dry-run` (T-03); search is cached, throttled and debounced (T-04); every modal action re-resolves the album
through `user_id` (T-05); provider JSON is read through `data_get()` with defaults (T-07); the worker no longer sleeps
(T-08).
