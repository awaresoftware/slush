# CONTEXT — Artwork import fix + web artwork search

> Decisions below were made by the user in discussion. They are **LOCKED**. The planner
> must not revisit them; the executor must implement them as written.

## Problem statement

Album artwork is silently not imported / not rendered. Investigated against the live
SQLite DB and the real `storage/app/public/covers/` directory.

## Verified diagnosis (evidence, not assumption)

1. **36% of albums have no artwork.** 485 of 1342 albums have `cover_art_path IS NULL`.
   All 485 have a non-empty `artist`, so the MusicBrainz query would have matched.
2. **The online backfill has never run.** `FetchAlbumArtwork` is dispatched from exactly
   one call site — the manual `albums:fetch-missing-artwork` command
   (`routes/console.php:45`). It is never dispatched from `ScanLinkedFolder`,
   `ExtractAudioMetadata`, or `UploadModal`. There are **0** `album-artwork-miss:*` rows
   in the `cache` table, proving the command has never completed a run.
3. **Garbage art wins the race and locks in forever.** `ExtractAudioMetadata.php:166,170`
   takes `picture[0]` with no `picturetype` filter. Real measured dimensions of the
   existing covers: **22× `72x72`, 5× `1x1`, 2× `100x100`, 1× `0x0`**, 21× `300x300`.
   The 1x1/0x0/72x72 files are placeholder/garbage images rendered as if they were
   real covers. First-write-wins at `ExtractAudioMetadata.php:158` and
   `FetchAlbumArtwork.php:52` means they can never be replaced.
4. **MIME→extension mismatch is possible.** `Album.php:87-92` maps MIME to extension with
   `default => 'jpg'`. BMP/TIFF/SVG/unknown embedded art is written as `.jpg` with
   mismatched bytes. (Currently 0 such files on disk — 1684 `image/jpeg`, 40 `image/png`
   — but the bug class is live for any newly scanned file.)
5. **No byte validation.** `$picture['data']` is written verbatim with no
   `getimagesizefromstring()` check.
6. **No image pipeline.** Album art bypasses Intervention Image entirely. The avatar flow
   (`resources/views/pages/settings/⚡profile.blade.php:52-64`) is the only place in the
   codebase that uses it (`cover(400,400)` + `toWebp()`).
7. **Nothing degrades gracefully on load failure.** None of the 12 `<img>` render sites
   has an `onerror`/`@error` fallback, so a 404 or undecodable file shows the browser's
   broken-image glyph rather than the app's musical-note fallback. This is why bad art
   reads as "not rendering" instead of "no cover".
8. **Media Session MIME is hardcoded.** `resources/js/app.js:106` sends
   `type: 'image/jpeg'` for all artwork — wrong for the 40 PNG covers.
9. **Disk waste.** 1724 files / 309 MB in `covers/`. Only 857 are referenced; **867 are
   orphans** from deleted albums (no album row points at them, and no orphan ID has a
   DB-referenced sibling). 78 files exceed 500 KB; the largest is 1.9 MB of raw PNG.
10. **No provenance.** No `artwork_source` column, no enum, no upload route, no policy,
    no Livewire component. "Custom artwork" cannot be expressed at all today.
11. **MB/CAA cannot power a picker.** `FetchAlbumArtwork` resolves one release group and
    takes `front-500` — a single image, no browse. It cannot back a search-and-pick UI.

## Locked decisions

### D1 — Search providers: iTunes + Deezer, keep MusicBrainz/Cover Art Archive

- **iTunes Search API** — primary picker. No key. Verified live:
  `GET https://itunes.apple.com/search?term={q}&entity=album&limit=N`
  Returns `results[]` with `collectionId`, `collectionName`, `artistName`,
  `artworkUrl100`, `releaseDate`, `trackCount`, `primaryGenreName`.
  Upgrade the image by substituting `100x100bb` → `600x600bb` in `artworkUrl100`
  (verified: the URL is a `.../100x100bb.jpg` thumb path).
- **Deezer** — alternate-candidate source. No key. Verified live:
  `GET https://api.deezer.com/search/album?q={q}&limit=N`
  Returns `data[]` with `id`, `title`, `artist.name`, `cover_xl` (1000×1000),
  `cover_big` (500×500), `nb_tracks`, `release_date`, plus `total`.
- **MusicBrainz + Cover Art Archive stay** as the silent automatic backfill only.
  Do not add Last.fm, Discogs, or Spotify. Do not add an API key or a new dependency.
- Both providers must degrade independently: a Deezer timeout must not break the
  iTunes tab, and vice versa.

### D2 — UI: album-page modal only

- A "Change artwork" action on `resources/views/pages/library/album-show.blade.php`
  opening a modal with: a search input, a provider tab switcher (iTunes / Deezer), a
  results grid, click-to-apply, a drag-and-drop local file upload, and a Remove action.
- **No** hover/context menu on album cards.
- **No** dedicated global artwork-manager page.
- **No** bulk fetch button in the UI (D6 covers auto-dispatch instead).
- Follow the existing avatar-upload precedent for the upload half
  (`resources/views/pages/settings/⚡profile.blade.php:16,50-64,184-189`,
  `app/Concerns/ProfileValidationRules.php:39-42`).

### D3 — Provenance: `artwork_source` enum, manual always wins

- Add `artwork_source` to `albums` as a string column cast to a new enum
  (`app/Enums/ArtworkSource.php`) with cases `Embedded`, `Fetched`, `Uploaded`, `Manual`.
  Use TitleCase keys and snake_case string values, matching `app/Enums/SourceType.php`.
- Re-scans, metadata re-extraction, and the MB/CAA backfill **must never** overwrite
  `Uploaded` or `Manual`.
- Provide a "Use auto-detected again" action that resets the album to a non-manual
  source and re-runs detection.

### D4 — Image pipeline: normalize everything to WebP, 600px max, quality 80

- Every artwork write path (embedded extraction, MB/CAA fetch, local upload, web pick)
  runs through Intervention Image v3.11.8: scale down to max **600px** on the longest
  edge, never upscale, encode **WebP quality 80**.
- One canonical filename: `covers/{album_id}.webp`. Writing a new cover **replaces** the
  old one — delete the previous file (including a differently-extended predecessor)
  rather than orphaning it.
- This permanently kills the MIME/extension mismatch class from diagnosis item 4.
- Files land smaller (~30–50 KB typical) instead of up to 1.9 MB.

### D5 — Backfill command: re-encode, repoint, prune orphans

One-off Artisan command that:
1. Re-encodes every referenced cover to `covers/{id}.webp` at 600px/q80, updates
   `cover_art_path`, and deletes the old file.
2. Deletes the **867 orphaned** cover files that no album row references.
3. Deletes covers that fail validation or are below the minimum-dimension threshold
   (clears the 1x1 / 0x0 / 72x72 garbage in one pass) and nulls `cover_art_path` so
   D6's auto-fetch can pick them up.
4. Is idempotent and safe to re-run. Must not touch audio files or DB rows otherwise.

### D6 — Auto-dispatch + fix the job itself

- Dispatch `FetchAlbumArtwork` automatically when an album ends a scan/upload with no
  artwork, from `ExtractAudioMetadata` / `ScanLinkedFolder` / `UploadModal`.
- Fix the job's own defects:
  - Remove the blocking `usleep(1100000)` at `FetchAlbumArtwork.php:72` — 485 albums
    would otherwise burn ~9 minutes of pure worker sleep. Rate-limit without blocking
    (e.g. a cache-based token gate) or drop the artificial delay.
  - Add a real `backoff()` so the existing 503-retry intent at `:164-166` is actually
    true. Today `tries = 3` retries immediately with zero delay.
  - Add `ShouldBeUnique` so N tracks of one album do not enqueue N jobs.
  - Respect D3: skip albums whose `artwork_source` is `Uploaded` or `Manual`.

### D7 — Embedded-art extraction: full fix set

All of the following, in `ExtractAudioMetadata::extractCoverArt()`:
1. **Filter by `picturetype`** — prefer `'Cover (front)'`; only fall back to another
   picture if no front cover exists.
2. **Best-of selection, not blind `[0]`** — when several pictures are present, rank them
   (front cover first, then largest pixel area) instead of taking index 0.
3. **Reject tiny/degenerate images** — anything under ~100px on an edge, or 1×1 / 0×0,
   is discarded as garbage.
4. **Validate bytes** with `getimagesizefromstring()` before writing.
5. **Allow re-extraction to replace bad existing art** when the existing art is
   degenerate or failed validation (D5 leaves this state behind).

### D8 — Search request policy: cache + throttle

- Cache search responses **24h**, keyed `artwork-search:{provider}:{normalized_query}`.
  Matches the existing `album-artwork-miss:{album_id}` cache-key convention.
- Debounce the search input ~400ms client-side (Alpine, as used in
  `resources/views/livewire/upload-modal.blade.php:31-35`).
- Add a per-user `RateLimiter` on the search action so bursts get a 429 rather than
  silent upstream throttling. iTunes asks for ≤20 req/min.
- Use the established outbound-HTTP pattern from `FetchAlbumArtwork::request()`
  (`Http::withHeaders([...])->timeout(20)`, explicit User-Agent).

### D9 — Search input: pre-filled, editable, no auto-search

- Pre-fill the search box with `"{album title} {artist}"`, editable by the user.
- **No automatic search on modal open** — the user presses the button. No surprise
  network calls.
- One single combined input, not separate title/artist fields.

### D10 — Graceful degradation

- Add an `onerror`/`@error` fallback to the album artwork render sites so a 404 or
  undecodable file degrades to the existing musical-note glyph instead of a
  browser broken-image icon. At minimum: `components/ui/album-card.blade.php`,
  `pages/library/album-show.blade.php`, `components/ui/track-row.blade.php`, and the
  `audio-player.blade.php` desktop/queue images.
- Fix the hardcoded `type: 'image/jpeg'` Media Session MIME at
  `resources/js/app.js:106` to derive from the actual file.

## Non-goals (explicitly out of scope)

- Last.fm / Discogs / Spotify / any API key or new composer dependency.
- Track-level artwork. Art stays album-level via `albums.cover_art_path`.
- Any change to audio file storage, scanning scope, or the music player.
- Deleting or moving the 867 orphan files as part of normal runtime (D5 only).
