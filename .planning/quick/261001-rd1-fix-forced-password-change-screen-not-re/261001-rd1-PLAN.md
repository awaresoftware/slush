<objective>
Make the mandatory password-change screen send the user onward once they save, while leaving the voluntary settings password change exactly as it is.

Purpose: `ForcePasswordChange` traps an authenticated user with `force_password_change = true` onto `/settings/password` and bounces every other authenticated route back there. `updatePassword()` already clears the flag and updates the password — but it ends with a `dispatch('password-updated')` and no navigation, so the trap has no exit. The user is released by the database write but not by the screen, which is the reported symptom: the password changes, "Saved." flashes, and the page simply sits there. The fix is a branch on the flag that already exists in the method.

Output: One conditional redirect in the component's `updatePassword()`, and two tests pinning both halves of the branch.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Livewire component action → user record | `updatePassword()` writes `password` and `force_password_change` from a Livewire action callable by the authenticated user on a `livewire/update` request. The middleware deliberately allows `livewire/update` through, so this write path is reachable by anyone holding a session for a user with the flag set. |
| Redirect target → middleware re-evaluation | The component names a destination route, and the browser then issues a fresh GET that re-runs `ForcePasswordChange` against the committed row. The ordering between the flag write and the redirect crosses this boundary. |
