## Phase Details

### Phase 12: Data Foundation
**Goal**: The database schema and Track model correctly support both uploaded and local-linked tracks, with path normalisation and source discrimination in place
**Depends on**: Nothing (first phase of v1.2)
**Requirements**: DATA-01, DATA-02, DATA-03
**Success Criteria** (what must be TRUE):
  1. Track records store a `source_type` value (uploaded vs local-linked) and existing tracks default to uploaded
  2. Track `audioUrl()` returns the correct URL for uploaded tracks and a streaming route URL for local tracks
  3. Absolute file paths stored in the database are normalised to forward slashes regardless of OS path separator
  4. The `linked_folders` table exists and the LinkedFolder model is usable with factory support
  5. ID3 metadata extraction job accepts and processes absolute paths for local-linked tracks
**Plans**: 2 plans
Plans:
- [ ] 12-01-PLAN.md — Schema, enums, LinkedFolder model, Track model enhancements
- [ ] 12-02-PLAN.md — ID3 job modification and comprehensive phase tests

### Phase 13: Authenticated Streaming
**Goal**: Local audio files can be securely streamed through an authenticated route with full HTTP Range/seeking support
**Depends on**: Phase 12
**Requirements**: STRM-01, STRM-02, STRM-03
**Success Criteria** (what must be TRUE):
  1. Visiting `/stream/{track}` while authenticated plays the audio file from its absolute path
  2. Unauthenticated requests and requests for another user's tracks are rejected with 403
  3. Path traversal attempts (e.g., paths outside registered linked folders) return 403
  4. HTML5 audio seeking works in Chrome/Edge/Safari (HTTP 206 Range responses served correctly)
**Plans**: 2 plans
Plans:
- [ ] 13-01-PLAN.md — StreamController, TrackPolicy, route, and tests (TDD)
- [ ] 13-02-PLAN.md — Unified audioUrl() and player auto-skip on error

### Phase 14: Scan Job & Metadata Pipeline
**Goal**: A queued job recursively discovers all audio files in a linked folder, extracts ID3 metadata, and auto-creates albums — all without blocking the UI
**Depends on**: Phase 12
**Requirements**: FOLD-02, FOLD-04, LIBR-04
**Success Criteria** (what must be TRUE):
  1. Dispatching a scan job for a linked folder creates Track records for every MP3, WAV, FLAC, M4A, AAC, and OGG file discovered recursively
  2. Each discovered track has ID3 title, artist, and duration populated (falling back to filename where tags are absent)
  3. Albums are auto-created from ID3 album tags; folder name is used as fallback when no album tag exists
  4. Rescanning an already-scanned folder does not create duplicate tracks
**Plans**: 2 plans
Plans:
- [ ] 14-01-PLAN.md — ScanLinkedFolder job with recursive discovery, duplicate prevention, and tests
- [ ] 14-02-PLAN.md — ExtractAudioMetadata extensions for cover art, album artist, folder fallback

### Phase 15: Folder Linking UI
**Goal**: Users can link folders, see linked tracks alongside uploaded tracks in the library, and identify track sources at a glance
**Depends on**: Phase 13, Phase 14
**Requirements**: FOLD-01, FOLD-03, FOLD-05, FOLD-06, LIBR-01, LIBR-02, LIBR-03
**Success Criteria** (what must be TRUE):
  1. User can enter a folder path in the UI and the app validates it is readable before starting a scan
  2. User can link multiple folders from different locations and each appears in a managed list
  3. Linked tracks appear in the library page alongside uploaded tracks with no functional difference
  4. Each track displays a source badge that visually distinguishes local-linked from uploaded
  5. Linked tracks are playable, searchable, and addable to playlists and the queue
  6. User can remove a linked folder and its tracks are removed from the library
**Plans**: 2 plans
Plans:
- [ ] 15-01-PLAN.md — Linked folders settings page with CRUD, polling, removal modal
- [ ] 15-02-PLAN.md — Source badges across track listings and source filter dropdown

### Phase 16: Missing File Detection & Polish
**Goal**: The app reliably detects when linked files have been moved or deleted and provides a way for users to recover
**Depends on**: Phase 15
**Requirements**: LIBR-05, LIBR-06
**Success Criteria** (what must be TRUE):
  1. Tracks whose files no longer exist on disk are marked unavailable and display a visual indicator in the library
  2. Missing file detection runs as a background job and never blocks page render
  3. User can update the path of a moved file to re-link it and restore its available state
**Plans**: 3 plans
Plans:
- [ ] 16-01-PLAN.md — Migration, model changes, ScanLinkedFolder detection, StreamController guard
- [ ] 16-02-PLAN.md — Unavailable track UI indicators, source filter, queue exclusion, skip toast
- [ ] 16-03-PLAN.md — RelinkTrackModal component and bulk folder path update
