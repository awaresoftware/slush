    - GET /register returns 200 when no users exist
    - Email verification feature is disabled (MustVerifyEmail not enforced, no verification email sent)
  </behavior>
  <action>
    1. Update app/Actions/Fortify/CreateNewUser.php:
       In the create() method, before User::create(), determine is_admin:
       ```php
       $isFirstUser = User::count() === 0;

       return User::create([
           'name' => $input['name'],
           'email' => $input['email'],
           'password' => $input['password'],
           'is_admin' => $isFirstUser,
       ]);
       ```
       Do NOT add hash() — 'password' cast is already set to 'hashed' in the model.

    2. Create middleware: php artisan make:class app/Http/Middleware/RequireNoUsers --no-interaction
       Implement as a standard Laravel middleware with handle():
       ```php
       public function handle(Request $request, Closure $next): Response
       {
           if (User::count() > 0) {
               abort(404);
           }

           return $next($request);
       }
       ```

    3. Register in bootstrap/app.php using appendToGroup or by assigning the middleware to specific routes:
       In withMiddleware():
       ```php
       $middleware->alias(['require.no-users' => \App\Http\Middleware\RequireNoUsers::class]);
       ```
       Then in routes/auth.php (or wherever Fortify register routes are defined), or use:
       ```php
       $middleware->appendToGroup('web', []);
       ```
       Actually — Fortify registers /register automatically. Use prependToGroup or route-specific:
       Check if routes/fortify.php exists or Fortify uses its own route registration.
       The cleanest approach: in withMiddleware(), add to the 'web' group conditionally,
       OR create a route macro. The best approach for Fortify: in withMiddleware(), use:
       ```php
       $middleware->alias(['require.no-users' => \App\Http\Middleware\RequireNoUsers::class]);
       ```
       Then in routes/web.php, you CANNOT easily add middleware to Fortify's auto-registered routes.
       Instead, override Fortify's route registration: publish Fortify routes with
       php artisan vendor:publish --tag=fortify-routes --no-interaction
       If that doesn't work, use the FortifyServiceProvider approach: in AppServiceProvider
       or FortifyServiceProvider, use Fortify::registerView() and add the middleware via
       a route group. The SIMPLEST approach that works with Fortify's auto-routing:
       In FortifyServiceProvider (app/Providers/FortifyServiceProvider.php),
       use Route middleware on the Fortify router — check how the project's
       FortifyServiceProvider is structured and add the middleware there.

    4. In config/fortify.php, remove Features::emailVerification() from the features array.
