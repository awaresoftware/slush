    - Test: moved file (different path, same hash) updates existing track's file_path instead of creating new
    - Test: individual unreadable file is skipped, rest of folder continues scanning
  </behavior>
  <action>
    Create `app/Jobs/ScanLinkedFolder.php` implementing ShouldQueue with LinkedFolder constructor injection.

    Job handle() logic per user decisions:
    1. Set folder status to `FolderStatus::Scanning`
    2. Create RecursiveIteratorIterator wrapping RecursiveDirectoryIterator with SKIP_DOTS
    3. Filter to supported extensions: mp3, wav, flac, m4a, aac, ogg (case-insensitive)
    4. For each audio file, in try/catch (skip on error, log warning):
       a. Normalise path to forward slashes BEFORE any DB lookup
       b. Compute md5_file() hash
       c. Check for existing Track by file_path first (same user), then by file_hash
       d. If path match: update file_hash, dispatch ExtractAudioMetadata
       e. If hash match (moved file): update file_path, dispatch ExtractAudioMetadata
       f. If no match: Track::create with source_type=Local, title=filename without extension, artist="Unknown Artist", duration=null; dispatch ExtractAudioMetadata
       g. Increment processed counter
    5. On success: update folder status=Active, track_count from DB count (not loop counter per pitfall 3), last_scanned_at=now()
    6. On outer exception: set folder status=Error, re-throw

    Use `$this->folder->tracks()->count()` for accurate track_count after loop.

    For tests: create real temporary directories with real audio files where possible, or empty files for structure tests. Use Queue::fake() to assert ExtractAudioMetadata dispatches. Use `php artisan make:test --pest ScanLinkedFolderTest` to scaffold.

    Run `vendor/bin/pint --dirty` after implementation.
  </action>
