# Requirements: Foonk

**Defined:** 2026-03-18
**Core Value:** Users can upload, organize, and stream their personal music collection

## v1.2 Requirements

Requirements for Local Library Linking milestone. Each maps to roadmap phases.

### Folder Management

- [x] **FOLD-01**: User can add a local folder path to link to their library
- [x] **FOLD-02**: App recursively scans linked folder discovering all audio files (MP3, WAV, FLAC, M4A, AAC, OGG)
- [x] **FOLD-03**: User can link multiple folders from different locations
- [x] **FOLD-04**: User can trigger a rescan on a specific linked folder
- [x] **FOLD-05**: User can see scan progress while folder is being processed
- [x] **FOLD-06**: User can remove a linked folder (tracks from that folder removed from library)

### Streaming

- [x] **STRM-01**: App serves linked audio files from absolute paths via authenticated route
- [x] **STRM-02**: Streaming supports HTTP Range requests for seeking
- [x] **STRM-03**: Streaming validates file ownership and path is within a registered linked folder

### Library Integration

- [x] **LIBR-01**: Linked tracks appear in existing library alongside uploaded tracks
- [x] **LIBR-02**: Tracks display source badge indicating local-linked vs uploaded
- [x] **LIBR-03**: Linked tracks work with existing search, playlists, and queue
- [x] **LIBR-04**: Albums auto-created from folder structure or ID3 album tags
- [x] **LIBR-05**: Missing files detected and marked as unavailable with visual indicator
- [x] **LIBR-06**: User can re-link a moved file by updating its path

### Data Foundation

- [x] **DATA-01**: Track model supports source type (uploaded vs local-linked)
- [x] **DATA-02**: Absolute file paths stored and normalized (Windows backslash handling)
- [x] **DATA-03**: ID3 metadata extracted for linked files using existing pipeline

## Future Requirements

### Advanced Scanning

- **SCAN-01**: Auto-detect filesystem changes and prompt user to rescan
- **SCAN-02**: Duplicate detection across uploaded and linked tracks

## Out of Scope

| Feature | Reason |
|---------|--------|
| Real-time filesystem watching | Requires daemon/supervisor, overkill for personal app |
| Auto-merge duplicates | Destructive — show source badge, let user decide |
| Symlinks to public directory | Security risk — use authenticated streaming route |
| Folder browsing UI (file picker) | Path input is sufficient; no server-side file browser needed |
