# Requirements: Foonk

**Defined:** 2026-03-26
**Core Value:** Users can upload, organize, and stream their personal music collection

## v1.3 Requirements

Requirements for Easy Installation milestone. Each maps to roadmap phases.

### Native Installation

- [x] **NATV-01**: User can install the project with a single `composer run setup` command (includes storage:link, key generation, migrations, npm build)
- [x] **NATV-02**: App detects port conflicts and suggests an available alternative port before starting
- [x] **NATV-03**: Queue worker auto-starts alongside web server and Vite when user runs `composer run dev`

### Install Scripts

- [x] **INST-01**: User can run `install.sh` on macOS/Linux to detect missing dependencies (PHP 8.x, Composer, Node) and get guided installation prompts
- [x] **INST-02**: User can run `install.ps1` via `install.bat` wrapper on Windows to detect missing dependencies and get guided installation prompts
- [x] **INST-03**: Install script offers to install Homebrew on macOS if missing, with explanation of why it's needed
- [x] **INST-04**: Repository includes `.gitattributes` enforcing LF line endings for shell scripts to prevent CRLF breakage on Windows

### Docker Installation

- [x] **DOCK-01**: User can start the full app in Docker via Laravel Sail with MySQL, Redis, and queue worker services
- [x] **DOCK-02**: `.env.docker.example` provides complete Docker-specific environment configuration as a standalone file
- [x] **DOCK-03**: User can mount host music folder into Docker container via `MUSIC_LIBRARY_PATH` environment variable for local library linking
- [x] **DOCK-04**: Docker services use healthchecks with `depends_on: condition: service_healthy` to prevent migration race conditions

### Health & Verification

- [x] **HLTH-01**: `/healthz` endpoint verifies app and database connectivity, used by install scripts to confirm successful setup

### Documentation

- [x] **DOCS-01**: README has separate installation sections for macOS, Linux, Windows, and Docker with step-by-step guides
- [x] **DOCS-02**: Docker documentation prominently explains that linked folder paths must use container paths (e.g. `/music`) not host paths

## Out of Scope

| Feature | Reason |
|---------|--------|
| Production Docker image | Overkill for personal self-hosted app |
| WSL2 auto-setup | Requires admin elevation and reboot; document instead |
| Laravel Horizon | Overkill for personal app queue needs |
| Pre-built Vite assets in Docker | Run once at install, not every container restart |
| Uninstall/cleanup commands | Out of scope for v1.3 per user decision |
