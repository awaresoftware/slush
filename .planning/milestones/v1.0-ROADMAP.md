# Roadmap: Spotify Clone

## Overview
This roadmap outlines the development of a personal audio streaming application inspired by Spotify. The application will allow users to upload, organize, and stream their personal music collection.

## Phases

| # | Phase | Goal | Requirements | Success Criteria |
|---|-------|------|--------------|------------------|
| 1 | 5/4 | Complete   | 2026-03-09 | Users can register, verify email, reset password, and log in |
| 2 | 3/3 | Complete   | 2026-03-04 | Users can create profiles with display name, avatar, bio, and view others' profiles |
| 3 | Music Library | Implement music upload and organization features | MUSC-01, MUSC-02, MUSC-03, MUSC-04 | Users can upload audio files, organize into albums/playlists, view library, search own collection |
| 4 | 1/1 | Complete   | 2026-03-10 | Users can play, pause, skip tracks, adjust volume, and see playback position |

### Phase Details

**Phase 1: Authentication System**
Goal: Establish secure user authentication with admin-controlled access
Requirements: AUTH-01, AUTH-02, AUTH-03, AUTH-04
**Plans:** 5 plans

Plans:
- [x] 01-01-PLAN.md — Database foundation: is_admin column, auto-admin first user, registration gate middleware
- [x] 01-02-PLAN.md — Auth UI: DaisyUI dark Spotify theme for all auth views
- [x] 01-03-PLAN.md — Invite system: UserInvitation model, notification, accept-invite flow
- [x] 01-04-PLAN.md — Admin user management: settings page with invite/delete, test suite completion
- [ ] 01-05-PLAN.md — Gap closure: replace welcome page with smart auth-state redirects on /

Success criteria:
1. User registration form with validation (first user only, gate closes after)
2. Invite-based user creation workflow (admin sends invite, user sets password)
3. Password reset functionality
4. Session management across browser refreshes with remember me

**Phase 2: User Profiles**
Goal: Enable user profile creation and management
Requirements: PROF-01, PROF-02, PROF-03, PROF-04
Success criteria:
1. Profile creation with display name
2. Avatar upload functionality
3. Bio field with character limit
4. Public profile viewing for other users

**Phase 3: Music Library**
Goal: Implement core music management features — batch audio upload with async ID3 extraction, album-based organization, tabbed library view, and inline search
Requirements: MUSC-01, MUSC-02, MUSC-03, MUSC-04
**Plans:** 4 plans

Plans:
- [x] 03-01-PLAN.md — Database foundation: Album + Track models, migrations, factories, getid3 install, AudioValidationRules concern, Livewire 100 MB config
- [x] 03-02-PLAN.md — Upload pipeline: library index Livewire component with upload modal, ExtractAudioMetadata queue job, all /library/* route registrations
- [x] 03-03-PLAN.md — Album show page + upload summary page: dedicated album detail view with track list, post-upload confirmation page
- [x] 03-04-PLAN.md — Library tabs + search: Tracks/Albums tabbed UI, album card grid, empty state, real-time debounced search

Success criteria:
1. Audio file upload with supported formats (MP3, WAV, FLAC, M4A, AAC, OGG), max 100 MB
2. Organization into albums (auto-created from ID3 tags or selected in upload modal)
3. Library view with Tracks tab (table) and Albums tab (card grid)
4. Search functionality — as-you-type with 300ms debounce, filters tracks and albums

**Phase 4: Audio Player**
