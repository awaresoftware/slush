## Phase Details

### Phase 17: Native Foundation
**Goal**: Users can install and run the app natively with single commands, with automatic port conflict detection
**Depends on**: Phase 16 (v1.2 complete)
**Requirements**: NATV-01, NATV-02, NATV-03
**Success Criteria** (what must be TRUE):
  1. Running `composer run setup` on a fresh clone completes the full install (key generation, migrations, storage link, npm build) without manual steps
  2. Running `composer run dev` starts the web server, Vite, and queue worker as a single process group
  3. If the default port is occupied, the app detects the conflict and suggests an available alternative before starting
**Plans**: 2 plans

Plans:
- [ ] 17-01-PLAN.md — Idempotent `composer run setup` with all install steps and Makefile removal
- [ ] 17-02-PLAN.md — Port conflict detection script and `composer run dev` integration

### Phase 18: Docker Configuration
**Goal**: Users can start the full app in Docker with a single command, including local library folder mounting
**Depends on**: Phase 17
**Requirements**: DOCK-01, DOCK-02, DOCK-03, DOCK-04
**Success Criteria** (what must be TRUE):
  1. Running `sail up -d` starts web, MySQL, Redis, and queue worker services with no manual configuration beyond copying `.env.docker.example`
  2. `.env.docker.example` is a complete, standalone file with all Docker-specific values pre-filled — no reference to `.env.example` needed
  3. Setting `MUSIC_LIBRARY_PATH` to a host folder mounts that folder into the container and makes it accessible for local library linking
  4. Services wait for their dependencies to be healthy before starting, preventing migration race conditions on first boot
**Plans**: 3 plans

Plans:
- [x] 18-01-PLAN.md — compose.yaml with web, MySQL, Redis, worker services + docker/start.sh entrypoint + Wave 0 test scaffold
- [x] 18-02-PLAN.md — .env.docker.example with complete Docker-specific environment configuration + .gitignore update
- [x] 18-03-PLAN.md — compose.music.yaml override template for optional music volume mount + full test validation

### Phase 19: Bash Install Script
**Goal**: macOS and Linux users can run a single script that detects missing dependencies and guides them through a complete install
**Depends on**: Phase 17
**Requirements**: INST-01, INST-03, INST-04
**Success Criteria** (what must be TRUE):
  1. Running `./install.sh` on macOS or Linux with missing dependencies (PHP, Composer, Node) prints specific guidance for installing each missing tool
  2. On macOS, if Homebrew is not installed, the script offers to install it with an explanation of why it is needed
  3. The script completes successfully and leaves the app in a runnable state on a clean macOS and Linux environment
  4. Shell scripts in the repository use LF line endings on all platforms including Windows checkouts, preventing broken bash execution
**Plans**: 1 plan

Plans:
- [ ] 19-01-PLAN.md — install.sh with dependency detection, auto-install, Homebrew prompt, and .gitattributes LF enforcement

### Phase 20: PowerShell Install Script
**Goal**: Windows users can run a single script that detects missing dependencies and guides them through a complete install without PowerShell execution policy errors
**Depends on**: Phase 19
**Requirements**: INST-02
**Success Criteria** (what must be TRUE):
  1. Running `install.bat` on Windows invokes the PowerShell script successfully without requiring the user to change execution policy manually
  2. The script detects missing dependencies (PHP, Composer, Node) and prints specific guidance for installing each missing tool on Windows
**Plans**: 1 plan

Plans:
- [ ] 20-01-PLAN.md — install.ps1 with Windows dependency detection, Herd PHP probing, Chocolatey auto-install, and install.bat UAC elevation wrapper

### Phase 21: Health Check Endpoint
**Goal**: A reliable endpoint verifies that both the app and database are operational, enabling install scripts to confirm successful setup
**Depends on**: Phase 17
**Requirements**: HLTH-01
**Success Criteria** (what must be TRUE):
  1. `GET /healthz` returns a JSON response with app and database status without requiring authentication
  2. The endpoint returns a non-200 status code when the database is unreachable, distinguishing a real failure from a web-server-only response
**Plans**: 1 plan

Plans:
- [ ] 21-01-PLAN.md — /healthz endpoint with DB connectivity check, install script hints, and Docker compose web healthcheck

### Phase 22: README Rewrite
**Goal**: Any user on any supported OS can open the README and follow a clear, accurate installation guide for their platform
**Depends on**: Phases 17, 18, 19, 20, 21
**Requirements**: DOCS-01, DOCS-02
**Success Criteria** (what must be TRUE):
  1. The README has distinct sections for macOS native, Linux native, Windows native, and Docker installation, each with step-by-step instructions
  2. The Docker section prominently explains that linked folder paths must use container paths (e.g. `/music`) not host paths, with an example
**Plans**: 1 plan

Plans:
- [ ] 22-01-PLAN.md — README.md with per-OS install guides, CONTRIBUTING.md, and LICENSE file
