<objective>
Create a single-instance AddToPlaylistModal Livewire component using the Mary UI modal pattern (`wire:model` boolean), replacing the per-track Flux modal pattern.

Purpose: The current add-to-playlist feature renders N hidden `<flux:modal>` elements (one per track) in the DOM. This refactors to a single Livewire component with `selectedTrackId` driven by event dispatch. This establishes the Mary UI modal pattern (MODAL-01) and the selectedTrackId single-instance pattern (MODAL-02) for the entire migration.

Output: Working `AddToPlaylistModal` component, updated trigger buttons on library/album pages, toast integration, old Blade component deleted, passing feature tests.
</objective>

    **Step 1: Create the Livewire component.**

    Run `php artisan make:livewire AddToPlaylistModal --no-interaction` to scaffold the component.

    Replace the generated PHP class with the full implementation from RESEARCH.md code example:
    - `use Mary\Traits\Toast` trait
    - `public bool $showModal = false` and `public ?int $selectedTrackId = null`
    - `#[On('open-add-to-playlist')] public function openForTrack(int $trackId)` — sets selectedTrackId and showModal
    - `public function closeModal()` — resets both properties to false/null
    - `public function addToPlaylist(int $playlistId)` — verifies ownership of track and playlist (both must belong to Auth::id()), checks for existing attachment to prevent duplicates, attaches with position = max+1, calls closeModal(), fires `$this->success("Added to {$playlist->name}")`
    - `#[Computed] public function selectedTrack(): ?Track`
    - `#[Computed] public function userPlaylists(): Collection` — returns `Playlist::where('user_id', Auth::id())->withCount('tracks')->orderBy('name')->get()`

    **Step 2: Create the Blade template.**

    Write `resources/views/livewire/add-to-playlist-modal.blade.php` using the template from RESEARCH.md:
    - Root `<div>` wrapper (required by Livewire)
    - `<x-mary-modal wire:model="showModal" title="Add to Playlist" box-class="max-w-sm">` — NO id prop
    - Show selected track title if `$this->selectedTrack` exists
    - If `$this->userPlaylists->isEmpty()` show empty state with link to create playlist
    - Otherwise show playlist list with `wire:key="{{ $playlist->id }}"` on each row
    - Each playlist row: `wire:click="addToPlaylist({{ $playlist->id }})"` — shows name and track count
    - Footer: "Create New Playlist" button linking to `route('playlists.create')`

    **Step 3: Create tests.**

    Run `php artisan make:test --pest AddToPlaylistModalTest --no-interaction`.

    Write Livewire component tests using `Livewire::test(AddToPlaylistModal::class)`:
    1. Component renders successfully
    2. `call('openForTrack', $track->id)` sets `showModal = true` and `selectedTrackId = $track->id`
    3. `call('closeModal')` resets both to false/null
    4. `call('addToPlaylist', $playlist->id)` after `openForTrack` attaches the track — assert DB has the pivot record
    5. Calling `addToPlaylist` twice does not create duplicate — assert pivot count is 1
    6. After `addToPlaylist`, `showModal` is false and `selectedTrackId` is null
    7. `userPlaylists` returns only the authenticated user's playlists, not other users'

    Use `actingAs(User::factory()->create())` for auth context. Create test data with factories.

    Run tests to verify GREEN.
